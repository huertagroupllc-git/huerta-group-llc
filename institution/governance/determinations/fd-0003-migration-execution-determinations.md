# fd-0003 — Founder Office Determinations: Migration and Evolution Log Execution Instrument (FO-1…FO-7)

**Classification: Institutional Record** — determination record
(evidentiary, non-governing).

- **Instrument:** Repository Foundation Project — Repository Migration
  and Institutional Evolution Log Activation task instrument, Founder
  Office → Platform & Systems Development (authorizing execution on the
  accepted Deliverables A–D as modified).
- **Received:** 2026-08-08, as transmitted to the implementing office.
- **Recorded:** 2026-08-08.

## Determinations (verbatim from the instrument)

- **FO-1:** "The repository shall remain a single repository." The
  instrument withdraws from execution planning: "Any Stage 2 repository
  split. Repository extraction. git filter-repo planning or execution.
  Dual-repository assumptions. New repository naming decisions.
  Repository-split ADRs." — "The migration terminates with the existing
  repository fully organized according to the approved
  single-repository architecture."
- **FO-2:** "The institution is not the repository. The repository is
  one institutional asset. A directory named institution/ may be used
  where approved by Deliverable C, but documentation shall describe it
  as containing the repository's canonical institutional governance
  assets. Do not use language implying that Huerta Group as an
  institution exists inside, is constituted by, or is equivalent to
  the repository."
- **FO-3:** "Minimize repository churn. Prefer moving coherent
  directories and preserving existing filenames where practical.
  Rename files only where a rename provides durable institutional
  value, resolves material inconsistency, or is specifically
  established by the approved architecture. Preserve Git history and
  repository familiarity wherever compatible with the target
  architecture."
- **FO-4:** "Repository Standards govern this repository. They are not
  standards governing Huerta Group as an institution generally.
  Preserve that scope distinction in metadata, documentation, and
  authority representation."
- **FO-5:** "Public website behavior is protected throughout this
  migration." (No public URL, routing, page, behavior, SEO, metadata,
  API, or inquiry changes; deployment behavior only as technically
  unavoidable for repository-only file movement and proven
  behavior-neutral.)
- **FO-6:** "The Institutional Evolution Log becomes Phase Zero
  immediately after migration." (Sequence: complete migration → verify
  integrity → implement Evolution Log → verify success criteria →
  return to operational status. "Do not begin website redesign during
  this assignment.")
- **FO-7:** "Migration is not complete until every required success
  criterion in this task is verified."

The instrument also recognizes the OSPA canonical recovery set
(OSPA-FND-V1-S01, S02, S03, S04, S09, S10) as recovered canonical
sources, identifies OSPA-FND-V1-RS05-EV01 as "a derived verified
evidence packet [that] must remain distinguishable from canonical
source," and prohibits inferring Sections 5–8 and 11–15 or
representing unavailable text as recovered canonical source. It
authorizes the previously-in-principle standard amendments
(model-neutral execution standards; Founder Office escalation
authority; duplication consolidated by reference).

## Affected artifacts

The entire repository structure (single-repository architecture); the
workbench and OSPA staging; the execution standards (authorized
amendments); the verification gate and minimal CI; the Institutional
Evolution Log.
