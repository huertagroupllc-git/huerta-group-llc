### 2.1 Historical record — the source did not reach Development with its authorization

*Retained as the accurate account of the period during which Development
held the authorization but not the requirements. It is not rewritten to
imply the text arrived sooner.*

The chronology, in order:

1. The Generation Two requirements existed institutionally, held by
   Corporate Operations & Command Management.
2. The Founder Office separately issued a bounded Generation Two
   implementation authorization to Institutional Platform Development —
   an execution package naming the Requirements Report first among its
   governing sources.
3. **The complete Requirements Report had not reached the Development
   runtime.** Development searched this repository and its git history, the
   sibling runtime repository, and the local filesystem, and found no copy.
4. **Development stopped rather than reconstructing it.** No section was
   inferred, synthesized, summarized, or assembled from the authorization
   package, from prior completion reports, from Generation One material, or
   from model memory. The precise failed completeness condition was
   returned to the Founder Office.
5. A second Founder Office instrument arrived carrying clarifications and a
   `<critical_source_gate>` restating the prohibition — but again without
   the report body. Development stopped a second time and returned the
   Founder Office's own specified sentence.
6. The Founder Office then transmitted the complete 37-section report.
7. Development verified completeness, computed the digest, and preserved
   the source. Construction resumed only afterwards.

This repeats the Generation One pattern (`fd-0010` D2, `fd-0011` D1,
`fd-0012` D2, discharged by `fd-0013`) and is recorded for the same reason:
so that the institution can see that its own transmission chain failed
twice, and that the implementing office refused twice to manufacture
requirements evidence rather than concealing the gap.

**Transmission medium.** Unlike Generation One — where the Founder Office
supplied files under `workbench/incoming/` and the digest was computed
before any repository copy existed — this source arrived as transmitted
text in the execution session. The digest above is therefore of the
preserved file itself, computed at preservation. Development records this
difference rather than implying a file-based chain of custody that did not
occur.

## 3. Authority boundary — what this report is and is not

The report is **business/operational requirements authority** for the
bounded Generation Two Command layer.

It is **not**:

- database authority;
- schema authority;
- application architecture authority;
- implementation authority;
- permission to create operational semantics absent from governing
  institutional authority;
- authority to widen any technical access class.

Its own §20 determines that **no major new semantic foundation is presently
required** and that Generation One semantics are sufficient. Its §22 states
that Development retains authority over implementation. Repository
preservation changes neither.
